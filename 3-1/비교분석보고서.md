# 비교 분석 보고서 (산출물 1)

> 같은 자동화 워크플로우를 노코드 도구 2개로 구현하고 비교한 기록입니다.
> ⚠️ 캡처에 나오는 토큰, API 키, 비밀번호는 `****`로 가리고, 이메일과 채팅 ID도 일부를 가립니다.

## 2. 공통 워크플로우 설계

두 도구에서 시작 이벤트, 핵심 액션, 분기 조건, 최종 결과를 똑같이 설정했습니다.

| 구분 | 내용 |
|---|---|
| 시작 이벤트 (트리거) | 매일 아침 7시 (한국 시간) |
| 핵심 액션 | Open-Meteo에서 강남구의 오늘 날씨(최고 기온, 최저 기온, 비 올 확률)를 가져옴 |
| 분기 조건 | ① 비 올 확률 60% 이상 ② 최저 기온 0도 이하 ③ 일교차(최고 − 최저) 10도 이상 중 하나라도 해당하는지 확인 |
| 최종 결과 | 해당하는 항목을 한 메시지에 모아 텔레그램으로 보냄 / 해당 없음이면 보내지 않음 |

```
[트리거] 매일 아침 7시
   ↓
[액션 1] 오늘 날씨 가져오기
   ↓
[조건 분기] 비 / 추위 / 일교차 확인
   ├─ 하나 이상 해당 → [액션 2] 텔레그램으로 모은 알림 보내기
   └─ 해당 없음 → 종료 (알림 없음)
```

## 3. 도구별 구현

### 3-1. Make

**구현 과정 요약**

1. Make에 Google 계정으로 가입하고, 프로필의 시간대를 Asia/Seoul로 바꿈
2. 새 시나리오를 만들고 이름을 `아침 날씨 알림`으로 정함
3. **HTTP (Make a request)** 블록을 추가하고 Open-Meteo 주소를 넣음 (Method: GET, Authentication: No authentication, Parse response 켬)
4. Run once로 실행해 Status Code 200과 `Data → daily` 안의 최고 기온, 최저 기온, 비 올 확률 값이 들어온 것을 확인함
5. **Telegram Bot (Send a Text Message or a Reply)** 블록을 추가하고 봇 토큰으로 연결, Chat ID를 넣어 "테스트" 메시지가 오는지 확인함
6. 텔레그램 메시지에 날씨 값과 `if()` 함수를 넣어 해당하는 알림 문구만 들어가게 함
7. 두 블록 사이 연결선에 **필터(깔때기)**를 만들고 비 / 추위 / 일교차 조건 3개를 OR로 연결함
8. 기준값을 잠깐 바꿔서 알림이 안 가는 경우도 테스트한 뒤 원래 값으로 되돌림
9. 시계 아이콘에서 실행 주기를 **Daily 07:00**으로 정하고 시나리오를 **Active**로 켬

**사용한 주소와 수식 (참고)**

날씨를 가져온 주소

```
https://api.open-meteo.com/v1/forecast?latitude=37.5172&longitude=127.0473&daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max&timezone=Asia%2FSeoul&forecast_days=1
```

텔레그램 메시지 내용

```
🌤 오늘 강남구 날씨 (최저 {{first(1.data.daily.temperature_2m_min)}}° / 최고 {{first(1.data.daily.temperature_2m_max)}}°)
{{if(first(1.data.daily.precipitation_probability_max) >= 60; "☔ 비가 올 수 있어요, 우산 챙기세요"; "")}}
{{if(first(1.data.daily.temperature_2m_min) <= 0; "🧣 많이 추워요, 따뜻하게 입으세요"; "")}}
{{if(first(1.data.daily.temperature_2m_max) - first(1.data.daily.temperature_2m_min) >= 10; "🧥 일교차가 커요, 겉옷 챙기세요"; "")}}
```

필터 `알림 조건` (OR)

| 조건 | 값 | 연산자 | 기준 |
|---|---|---|---|
| 비 | `first(1.data.daily.precipitation_probability_max)` | 이상 (Greater than or equal to) | 60 |
| 추위 | `first(1.data.daily.temperature_2m_min)` | 이하 (Less than or equal to) | 0 |
| 일교차 | `first(1.data.daily.temperature_2m_max) - first(1.data.daily.temperature_2m_min)` | 이상 (Greater than or equal to) | 10 |

### 3-2. Activepieces

**구현 과정 요약**

1. Activepieces에 Google 계정으로 가입함. 브라우저 자동 번역이 켜져 있어 화면 오류(removeChild)가 나서, 이 사이트는 번역하지 않도록 끄고 영어 화면으로 진행함
2. Personal Project → Build a Flow → Start from scratch로 새 플로우 `아침 날씨 알림`을 만듦
3. **Schedule (Every Day)** 트리거를 넣고 매일 7시, 시간대 Asia/Seoul, 주말에도 실행으로 설정함
4. **HTTP (Send HTTP request)** 블록에 Make와 같은 Open-Meteo 주소를 넣고(Method: GET) Test step으로 날씨 값을 확인함
5. 일교차를 조건 칸에서 바로 계산할 수 없어 **Math Helper (Subtraction)** 블록으로 최고 − 최저를 먼저 계산함
6. **Router** 블록을 넣고 Branch 1에 비 / 추위 / 일교차 조건 3개를 Or로 연결함. Otherwise는 비워 둠 (조건에 안 맞으면 아무것도 안 함)
7. Router에 "이상/이하" 연산자가 없어 "초과/미만"으로 바꾸고 기준값을 조정함
8. **Telegram Bot (Send Text Message)** 블록을 Branch 1 안에 넣고 봇 토큰으로 연결함. 날씨 값이 들어간 메시지에서 HTTP 400 오류가 나서 Format을 HTML로 바꿔 해결함
9. 메시지 칸에 조건 수식(if)을 넣을 수 없어서, 해당하는 문구만 모으는 부분은 AI에게 받은 코드를 **Code** 블록에 넣어 처리함 (한계기록서 [한계 1], 코드 시도 기록 참고)
10. Router 기준값을 잠깐 바꿔 Branch 1 경로와 Otherwise 경로를 모두 테스트하고, 전체 플로우(Test Flow)를 실행해 텔레그램 알림이 오는 것을 확인함
11. 기준값을 원래대로 되돌리고 Publish로 게시해 자동 실행을 켬

**사용한 조건 (Router Branch 1, Or)**

| 조건 | 값 | 연산자 | 기준 | Make 기준과 같은 이유 |
|---|---|---|---|---|
| 비 | HTTP `precipitation_probability_max` 0번 | (Number) is greater than | 59 | 비 올 확률은 정수라서 59 초과 = 60 이상 |
| 추위 | HTTP `temperature_2m_min` 0번 | (Number) is less than | 0.1 | 기온은 소수 한 자리라서 0.1 미만 = 0 이하 |
| 일교차 | Math Helper 결과 | (Number) is greater than | 9.9 | 소수 한 자리라서 9.9 초과 = 10 이상 |

## 5. 비교 항목 (5개 이상)

| 비교 항목 | Make | Activepieces |
|---|---|---|
| 화면 구성 | 동그라미 블록을 점선으로 이어 붙이는 방식 | 블록을 위에서 아래로 쌓는 방식 |
| 분기 설정 방법 | 블록 사이 연결선에 필터(깔때기)를 달고 조건을 OR로 추가 | Router 블록으로 길을 Branch 1 / Otherwise로 나누고 조건을 Or로 추가 |
| 비교 연산자 | 이상(≥), 이하(≤) 바로 선택 가능 | 초과(>), 미만(<)만 있어 기준값을 바꿔서 맞춤 |
| 스케줄(시간) 설정 방법 | 첫 블록의 시계 아이콘에서 Daily, 시간 입력 | Schedule 트리거 블록(Every Day)에서 시간과 시간대 입력 |
| 계산(일교차) 처리 방법 | 칸 안에 `-` 수식을 직접 써서 처리 | 조건 칸에서 계산이 안 돼 Math Helper 블록을 따로 추가 |
| 메시지에 조건부 문구 넣기 | 메시지 칸에 `if()` 수식으로 처리 | 메시지 칸에 조건 수식이 없어 Code 블록(코드)으로 처리 |
| 데이터 넣는 방법 | `{{ }}` 수식을 직접 쓰거나 붙여 넣기 | 데이터 선택 창에서 값을 클릭해서 넣기 |
| 텔레그램 연결 방법 | Telegram Bot 앱에 봇 토큰으로 연결하고 Chat ID 입력, 기본 설정으로 바로 전송됨 | 봇 토큰으로 연결하고 Chat ID 입력, 괄호와 점이 든 메시지에서 HTTP 400이 나서 Format을 HTML로 바꿔야 했음 |
| 테스트 방법 | Run once로 전체를 실행하고 블록마다 말풍선으로 결과 확인 | 블록마다 Test step으로 하나씩 테스트, 전체는 Test Flow |
| 무료 사용량 | 한 달 1,000 크레딧, 활성 시나리오 2개 | 한 달 1,000 크레딧 |
| 실행 기록 확인 | 상세 페이지의 History 탭 | 프로젝트의 Runs 탭 |
| 자동 실행 켜기 | 시나리오를 Active로 켬 | Publish로 게시해야 켜짐 |

> 11/25(Make), 11/26(Activepieces) 구현하면서 확인한 내용으로 채웠습니다. 보고서에는 이 중 5개 이상을 골라 쓰고, 표현은 직접 다듬습니다.
